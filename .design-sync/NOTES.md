# design-sync notes — LoomWatch

LoomWatch's `ui/` is an app, not a component library, so the synced "package" is a thin wrapper:
`docs/design-system/` (`@loomwatch/design-system`, global `window.LoomWatch`).

- **What ships.** Six standalone React glyphs re-exported unchanged from `ui/src/components/ui/`
  (`AgentMark`, `StatusGlyph`, `ChipDot`, `CoverageGlyph`, `EntityGlyph`, `LoomMark`) via
  `docs/design-system/src/index.ts`, plus the CSS kit (`tokens.css` + `components.css`) as
  `cfg.cssEntry` (`dist/loomwatch.css`). App components that need React Flow or run state
  (canvas cards, composer, inspector) are NOT exported. Their look ships as kit classes, and
  `.design-sync/conventions.md` teaches the class vocabulary.
- **Build before converting** (`cfg.buildCmd`): `sh docs/design-system/tools/sync.sh` (copies
  tokens + fonts from `ui/`, writes the `Inter Variable` alias) then
  `node docs/design-system/tools/build-package.mjs` (`ui/`'s own tsc emits `.d.ts` under
  `dist/types/`; `dist/types/index.d.ts` re-exports the entry so the whole tree sits under one
  types root; concatenates the CSS).
- **Project:** "LoomWatch Design System", https://claude.ai/design/p/bbeb2e23-afc8-43ee-be02-b0f126a5d00d
  (pinned in config). First uploaded 2026-10-01: 6 components, 45 content files plus the sentinel
  and `_ds_sync.json`.
- **Re-sync** (from repo root): re-stage `.ds-sync/` (base skill step 7), run `cfg.buildCmd`, save
  the project's `_ds_sync.json` to `.design-sync/.cache/remote-sync.json`, then
  `DS_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" node .ds-sync/resync.mjs --config .design-sync/config.json --node-modules ui/node_modules --entry docs/design-system/src/index.ts --out ./ds-bundle --remote .design-sync/.cache/remote-sync.json`
- **`/design-login`** is a Claude Code slash command: type it at an interactive `claude` prompt,
  not in a shell (zsh reads it as a path).
- **Fresh clone:** `ln -sfn ../../ui/node_modules docs/design-system/node_modules`. Without it,
  ts-morph can't find `@types/react` from the package dir (`[DTS_REACT]`) and `style` props
  degrade to `any`. The link is gitignored.
- **Render check browser:** no Playwright Chromium is cached. Validate/capture use system Chrome via
  `DS_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`, and
  `playwright` is installed in `.ds-sync/` with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`.
- **`[FONT_MISSING] "Inter Variable"`** was a fallback name in `--font-sans`. It is resolved by
  `fonts/aliases.css` (generated by `sync.sh`, listed in `cfg.extraFonts`), so don't suppress it.
- **Theme:** tokens are light on `:root`, dark under `[data-theme="dark"]`. `components.css`
  re-declares the tier-3 aliases under `[data-theme]` so a wrapper div can theme a subtree.
  Previews wrap every cell in dark + light panes.
- **Foundation cards** (`docs/design-system/preview/*.html`: colour, type, canvas cards, edges,
  Home…) are NOT uploaded: `guidelinesGlob` accepts only `.md`/`.mdx`, and shipping HTML would
  need a fork of `lib/docs.mjs`. `DESIGN.md` carries the same content as a guideline.

## Re-sync risks
- `docs/design-system/components.css` is a hand-curated copy of `ui/src/styles/*.css` selectors.
  When app component styles change, update it by hand (tokens and fonts re-sync automatically).
- `dist/loomwatch.css` concatenates `tokens.css` and `components.css`, so tokens arrive inside
  `_ds_bundle.css` and `tokens/` stays empty. The conventions header points the agent there.
- The glyphs are re-exported from `ui/src`. A rename or signature change there changes the shipped
  API. Re-run `build-package.mjs` and expect those components to re-verify.
- DESIGN.md's "Open conflicts" table describes the app as of 2026-10-01. Re-check it against `ui/`
  before trusting it.
